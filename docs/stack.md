# Стек StudyMate и почему он такой

Документ фиксирует технический стек проекта и причины выбора. Отдельно отмечены
решения, продиктованные не архитектурой, а доступным окружением: **Python 3.12**
выбран потому, что уже установлен локально, а **GigaChat API** — потому что для него
есть рабочие токены. Остальные решения — следствия требований проекта и ограничений
самой задачи.

## Общий принцип

StudyMate — учебный прототип с одним сценарием: загрузить лекцию в PDF, получить по ней
вопросы, пройти тест и увидеть разбор. Всё, что не обслуживает этот сценарий, не
добавлялось: нет кэшей, очередей, контейнеров, слоя миграций и клиентского
стейт-менеджера. Это осознанный выбор в пользу KISS, зафиксированный в `AGENTS.md`.

## Frontend

Текущий стек: React 19 + Vite 8, TypeScript, React Router 8, Tailwind CSS 4,
shadcn/ui на `@base-ui/react`, `lucide-react`, self-hosted шрифты.

### React + Vite

| | |
|---|---|
| **Взяли** | React 19 + Vite 8 (`@vitejs/plugin-react` 5.2) |
| **Альтернативы** | Next.js 16, Remix, SvelteKit, Vue, Solid, Create React App |

Главная причина — **весь интерфейс клиентский**. Токен доступа лежит в `localStorage`,
поэтому ни одна страница не может отрендериться на сервере в персонализированном виде:
все экраны и раньше начинались с `"use client"`. Значит, пользы от SSR нет, а издержки
Next.js остаются:

- экспериментальные флаги `cacheComponents` и `partialPrefetching` на приложении без
  серверного рендера ничего не дают;
- dev-индикатор в углу экрана — лишняя сущность, которую приходится отключать;
- для продакшена нужен Node-сервер, хотя весь результат — статические файлы.

Vite даёт `dist/` из статики (раздаётся любым хостингом), старт разработки за доли
секунды и никакой магии: нет `"use client"`, нет серверных компонентов. Миграция
выполнена в change `frontend-aurora-practice`, там же лежит подробное сравнение.

Другие альтернативы отклонены по одной причине: SvelteKit, Vue, Solid, Remix и
устаревший CRA означают переписать весь интерфейс ради нулевой выгоды для этого
приложения, а Remix/Next ценны именно серверным рендерингом, которого здесь нет.

### TypeScript

Контракт с backend небольшой, но с вложенными типами (`choice | open` у вопроса,
оценки открытых ответов). Типы ловят расхождение с API на сборке (`tsc --noEmit`
входит в `npm run build`), а не в браузере. Альтернатива — чистый JS — экономит
десять минут на старте и стоит отладки при каждом изменении схемы.

### React Router 8

Файловый роутинг Next был удобен, но давал мало: маршрутов четыре. В React Router взят
обычный `<BrowserRouter>` + `<Routes>`, **без** data-router и `loader`-ов: данные
загружаются с токеном из `localStorage`, то есть loaders всё равно были бы клиентскими,
а `useEffect` уже написан. Защита приватных маршрутов вынесена в один layout-маршрут
`RequireAuth` вместо проверки на каждой странице.

### Tailwind CSS 4

Утилитарные классы + CSS-переменные позволяют держать дизайн-систему в одном файле
(`src/styles/aurora.css`) и перекрашивать её без правок компонентов: темы, градиенты,
радиусы и тени живут в `@theme inline`.

| Альтернатива | Почему нет |
|---|---|
| CSS-модули / SCSS | медленнее итерация, нет токенов из коробки |
| styled-components, emotion | рантайм и вес в бандле, для статики не нужны |
| UnoCSS | меньшее сообщество, выгода неочевидна |

Отдельная причина — Tailwind 4 подключается к Vite одним плагином
(`@tailwindcss/vite`), без PostCSS-конвейера и `tailwind.config`.

### shadcn/ui на `@base-ui/react`

Компоненты копируются в репозиторий (`src/components/ui/`), поэтому их можно
перекрашивать и менять без борьбы с библиотекой.

| Альтернатива | Почему нет |
|---|---|
| MUI, Ant Design | свой дизайн-язык, который приходится переопределять; крупный бандл |
| Radix UI напрямую | тот же принцип, но shadcn уже настроен и даёт готовые стили |
| Свои компоненты с нуля | дольше, а доступность диалогов и полей пришлось бы делать руками |

### `lucide-react`

Иконки импортируются по одной и вырезаются тришейкингом, то есть в бандл попадают
только использованные. Альтернативы: Font Awesome (шрифт целиком), heroicons
(меньше набор).

### Шрифты Manrope + Inter через `@fontsource-variable`

Self-hosted, без запроса к Google Fonts: работает офлайн и не отдаёт данные наружу.
Главное ограничение — **кириллица**: интерфейс русский, а популярные «модные» шрифты
(Space Grotesk, Satoshi) её не содержат. Manrope и Inter содержат, поэтому заголовки —
Manrope, текст — Inter.

`next/font` был доступен только в Next.js; после переезда шрифты подключаются
пакетами Fontsource, где браузер скачивает только нужные подмножества по
`unicode-range`.

### Без библиотеки анимаций

Эффектов ровно четыре: появление карточек, hover-подъём, дрейф градиента и индикация
генерации. Это закрывается CSS-`@keyframes`, а переходы между шагами теста — View
Transitions API с проверкой поддержки. Библиотека вроде `motion` (~35 КБ gzip) ради
этого не окупается, и `AGENTS.md` требует сначала проверять, можно ли обойтись
имеющимся.

### `localStorage` для токена, `sessionStorage` для теста

- **Токен в `localStorage`** — переживает перезагрузку и не требует cookie-сессий на
  сервере. Минус известен: токен уязвим к XSS. Для прототипа принято; при выходе в
  прод-режим правильнее httpOnly-cookie и CSRF-защита.
- **Сгенерированный тест, ответы и результат — в `sessionStorage`.** По спеке
  `material-quiz` тест транзитивный и не сохраняется, а генерация занимает до минуты,
  поэтому терять её на F5 недопустимо. `sessionStorage` даёт нужную семантику: одна
  вкладка — один черновик, новая вкладка начинает с чистого листа. В ключ зашита
  версия (`studymate:practice:v1`), чтобы старый формат не ломал страницу.

### npm вместо pnpm/yarn

Проект уже был на npm с `package-lock.json`. Переход на pnpm дал бы экономию диска, но
потребовал бы менять документацию и способ установки ради выгоды, которой в проекте из
одного пакета нет.

### Почему `@vitejs/plugin-react` версии 5, а не 6 и не SWC

Версия 6 тянет peer-зависимости на Babel 8, которые конфликтуют с деревом Babel 7,
уже притянутым пакетом `shadcn`. Вариант `@vitejs/plugin-react-swc` быстрее, но
`@swc/core` требует postinstall-скрипт, а в текущем окружении сборки запуск дочерних
процессов запрещён. Версия 5.2 работает на Babel 7 и конфликта не создаёт; на результат
сборки выбор не влияет.

## Backend

Текущий стек: Python 3.12, FastAPI, Pydantic + pydantic-settings, SQLAlchemy 2.0,
SQLite, PyJWT, bcrypt, pdfplumber, langchain-gigachat, uvicorn, uv.

### Python 3.12

**Выбран потому, что уже установлен на машине разработчика** — разворачивать ещё одну
версию ради прототипа смысла нет. Дополнительный плюс: 3.12 даёт аккуратные
аннотации (`str | None`), `datetime.UTC` и актуальную поддержку библиотек.

Альтернативы: 3.13 (локально нет, выгоды для проекта нет), 3.11 и ниже (нет причин
откатываться).

### FastAPI

| Альтернатива | Почему нет |
|---|---|
| Flask | нет валидации схем, зависимостей и автодокументации из коробки — всё это пришлось бы собирать руками |
| Django + DRF | ORM, админка, шаблоны и структура проекта не нужны: API на пять роутеров |
| Litestar, Starlette «голый» | моложе либо требует больше ручной обвязки |
| Node/Go на бэкенде | библиотеки для PDF и GigaChat доступнее в Python |

FastAPI даёт три вещи, без которых проект стоил бы дороже: Pydantic-контракты запросов
и ответов, автоматический `/docs` для проверки API руками и `Depends` для сессии БД и
текущего пользователя.

### Pydantic + pydantic-settings

Двойная роль: валидация HTTP-контрактов **и** схема ответа языковой модели через
`with_structured_output`. Один и тот же класс `Quiz` описывает и то, что требует модель,
и то, что уходит клиенту — расхождение между ними невозможно. Инварианты (индекс
правильного ответа внутри списка вариантов, непустой эталонный ответ) проверяются
валидаторами, то есть ответ LLM проверяется до использования, как требует `AGENTS.md`.

`pydantic-settings` читает `.env` и строит пути от каталога `backend/`, а не от текущего
рабочего каталога, — иначе запуск из корня создавал бы вторую базу.

### SQLAlchemy 2.0 и SQLite

Сейчас база — файл `backend/studymate.db`. Это ноль инфраструктуры: клонировал, запустил,
данные на месте, базу видно и можно удалить при смене схемы.

**PostgreSQL заявлен как целевая БД**, но фактически проект работает на SQLite.
Переезд дешёвый: идентификаторы хранятся как `String(36)`, а не как PG-специфичный
`UUID`, и адрес задаётся одной переменной `DATABASE_URL`. Что понадобится при переезде —
миграции (сейчас схема создаётся `create_all`, который не меняет существующие таблицы).

Движок синхронный: нагрузки нет, async-драйвер добавил бы сложность без выгоды.

### JWT (PyJWT) и bcrypt

Аутентификация сделана без сессий на сервере: `HS256`-токен на 24 часа, в `sub` —
идентификатор пользователя.

| Альтернатива | Почему нет |
|---|---|
| Сессии в БД | нужна таблица сессий и её очистка — лишняя сущность для прототипа |
| OAuth-провайдеры | вне задачи проекта |
| `passlib` для bcrypt | падает при чтении версии `bcrypt>=4.1`; починка тянет лишние зависимости, поэтому `bcrypt` используется напрямую |

### pdfplumber

| Альтернатива | Почему нет |
|---|---|
| `pypdf` | быстрее, но хуже разбирает таблицы и порядок в двухколоночной вёрстке — а это типичная лекция |
| GigaChat `attachments` | модель читает документ, но текст наружу не отдаёт — только пересказ, то есть нестабильная основа для генерации |
| OCR сканов | вне scope: PDF без текстового слоя отклоняется с `422` |

Тонкости, найденные замерами и зафиксированные в коде: `x_tolerance=1` (значение по
умолчанию склеивает слова), `layout=True` не используется (раздувает число токенов).

### GigaChat API

**Взят потому, что для него есть рабочие токены** — без действующей учётной записи
AI-функциональность проверить было бы нельзя. Дополнительные плюсы: доступ по OAuth с
`credentials` (секрет живёт только на backend), российский провайдер и поддержка
структурированного ответа через `function_calling`.

| Альтернатива | Почему нет |
|---|---|
| OpenAI, Anthropic | нет доступа и токенов |
| локальная модель (Ollama и т. п.) | нет подходящего железа, а задержка выросла бы |
| самописный REST-клиент | пришлось бы вручную разбирать JSON ответа модели |

`langchain-gigachat` + `with_structured_output` закрывают главную боль — разбор ответа:
модель заполняет Pydantic-схему, а не свободный текст.

### Модель «оценки списком»

При проверке открытых ответов модель возвращает **список оценок в порядке отправки**, а
не пары «номер ответа — оценка». Номер привязывает сервер. Так модель физически не может
перепутать индексы и приписать оценку не тому вопросу. Все ответы уходят одним запросом:
у физлица один поток, и N отдельных вызовов заняли бы N минут.

### uv

Управляет версией Python, виртуальным окружением и зависимостями, есть `uv.lock`.
Заметно быстрее `pip` и не требует отдельного `requirements.txt`. `pip` в проекте не
используется намеренно — иначе появились бы два источника правды.

### Файловое хранилище вместо S3

Материалы лежат в `backend/storage/materials/{id}/{filename}`. S3, MinIO или любой
объектный сторедж — это отдельный сервис, ключи и сетевые ошибки ради файлов, которые
пока читает только backend при загрузке.

Ключевое свойство — **изоляция путей**: имя файла санитизируется, а запись всегда идёт в
каталог конкретного материала, поэтому `..` из имени файла никуда не выводит.

## Данные и AI: почему именно так

| Решение | Причина |
|---|---|
| Тест не сохраняется в БД (Transient Quiz) | прототип без истории попыток; «Результаты» честно остаются заглушкой |
| Тестовые ответы проверяет клиент | `correct_index` уже приходит в ответе генерации, проверка в браузере — ноль задержки. Осознанный компромисс: ответы видны в DevTools. Как только появятся назначения от преподавателя, проверка обязана переехать на сервер |
| Открытые ответы проверяет LLM | это ровно то, что обещает продукт: оценка по смыслу, а не по совпадению слов |
| Оценка 0–100 | целое число удобно суммировать и отображать, без плавающей точки в контракте |
| Лимит 30 000 токенов на материал | ≈52 страницы при замере 8 635 токенов на 15 страниц; длиннее — отказ `422` при загрузке, чтобы непригодный материал не попадал в базу |
| Не больше 15 тестовых и 10 открытых вопросов | ответ модели должен помещаться в её собственный лимит и приходить за минуту |
| Нет фоновых задач и очередей | генерация синхронная; брокер добавил бы статусы, опрос и второй процесс |

## Что осознанно не взяли

| Не взяли | Причина |
|---|---|
| Next.js | нет серверного рендера (см. выше) |
| PostgreSQL на текущем шаге | SQLite достаточно для прототипа; переезд — одна переменная + миграции |
| Alembic | данные одноразовые, схема пересобирается удалением файла БД |
| Redux, Zustand, React Query | состояние локальное, запросов единицы, кэша нет |
| Docker, CI, Kubernetes | один разработчик и один локальный стенд |
| Библиотека анимаций | эффекты закрываются CSS (см. выше) |
| Монорепозиторий с общими пакетами | две независимые части с REST-контрактом, дублирования нет |
| Автотесты backend | сейчас проверки идут скриптами и живыми вызовами API; постоянного набора тестов нет — это технический долг |

## Технический долг и компромиссы

1. **SQLite вместо PostgreSQL** — заявлено в README, но ещё не сделано.
2. **Нет миграций**: `create_all` не меняет существующие таблицы, при изменении моделей
   база удаляется.
3. **`gigachat_verify_ssl=False` локально** — окружение не доверяет цепочке GigaChat; для
   продакшена нужен `GIGACHAT_CA_BUNDLE_FILE` с корневым сертификатом.
4. **Токен в `localStorage`** — уязвим к XSS; правильнее httpOnly-cookie.
5. **Ответы теста видны в DevTools** — приемлемо для самоподготовки, неприемлемо для
   оценивания преподавателем.
6. **Результаты не сохраняются** — «Результаты» на дашборде остаются заглушкой.
7. **Нет автотестов backend** — проверки выполняются скриптами и живыми запросами к API.
8. **Проверка интерфейса без браузерных тестов** — вёрстка и анимации проверялись
   серверным рендером, расчётом контраста и типизацией, но не кликами в браузере.
