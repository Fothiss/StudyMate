# Proposal

## Why

Backend уже умеет регистрировать пользователя, выдавать токен и принимать учебные материалы, но воспользоваться этим можно только через `/docs` и curl. Продукт без браузерного клиента — это API, а не приложение, поэтому дальше развивать генерацию тестов, прохождение и статистику бессмысленно: результат некому показать.

Этот change создаёт первый работающий интерфейс: человек открывает страницу, входит, загружает лекцию и видит свои материалы. Одновременно он задаёт каркас навигации, в который потом лягут тесты и результаты.

## What Changes

- Новое приложение Next.js в `frontend/`: TypeScript, App Router, Tailwind CSS, shadcn/ui, пакеты через npm.
- Три страницы: `/login`, `/register` и `/` — главная с дашбордом. Отдельного `/materials` не заводится: при одной сущности дашборд и есть её список.
- Дашборд содержит блок «Мои материалы» (счётчик, последние загруженные, инлайн-загрузка файла, отдельное состояние для пустого списка) и два блока-объяснения для «Тесты» и «Результаты», которых backend пока не умеет.
- Клиент API с Bearer-токеном из `localStorage`: единая обработка `401` (сброс токена и переход на `/login`), человеческие тексты для `401`, `409`, `413`, `415`, `422`.
- Защита главной на клиенте: гость на `/` уезжает на `/login`; после регистрации выполняется автоматический вход и переход на дашборд.
- Заголовок приложения с логином пользователя и кнопкой «Выйти» — выход только на клиенте, эндпоинта logout в backend нет.
- Из учётных записей убирается полное имя: регистрация и профиль состоят только из логина и пароля. **BREAKING** для `user-auth` — меняется форма запроса на регистрацию и состав ответов `/auth/register` и `/users/me`.

## Capabilities

### New Capabilities

- `web-session`: поведение неаутентифицированного и аутентифицированного клиента — формы входа и регистрации, хранение токена, доступ к защищённой главной, выход и обработка истёкшей сессии.
- `web-dashboard`: главный экран приложения — сводка по материалам пользователя, загрузка нового материала и честное отображение разделов, которые ещё не реализованы.

### Modified Capabilities

- `user-auth`: регистрация и профиль описываются без поля полного имени — учётная запись состоит из уникального логина и пароля.

## Impact

- Новый код: `frontend/**` (создаётся с нуля, каталог сейчас пуст), `frontend/package.json`, конфигурация Next.js и Tailwind.
- Изменяемый код backend: `app/models/user.py`, `app/schemas/user.py`, `app/services/users.py` — из них убирается `full_name`. Колонка удаляется только пересозданием базы: `create_all` не умеет менять существующие таблицы, поэтому файл `backend/studymate.db` удаляется.
- Изменяемые файлы в корне: `.gitignore` (артефакты `node_modules`, `.next`, `.env.local`), `README.md` (раздел запуска frontend, который сейчас помечен «будет добавлен отдельным изменением»).
- Новые зависимости: `next`, `react`, `react-dom`, `tailwindcss`, компоненты shadcn/ui (`button`, `input`, `card`, `label`), `clsx`, `tailwind-merge`.
- Внешние требования: backend запущен на `http://127.0.0.1:8000`; адрес клиента задаётся через `NEXT_PUBLIC_API_URL`.
- Вне scope: генерация вопросов, прохождение тестов, проверка ответов, статистика, извлечение текста из документов, скачивание и предпросмотр файлов, удаление материалов, серверный рендеринг с авторизацией, тёмная тема, мобильная адаптация сверх стандартных брейкпоинтов Tailwind.
