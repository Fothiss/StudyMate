# Design

## Context

Backend не существует: в `backend/` есть только `pyproject.toml` от `uv init`, `.python-version` и `.venv`, созданный `uv`. Мотивация — в `proposal.md`, требования — в `specs/`.

Ограничения, которые формируют подход:

- **Окружение Windows.** Голый `python` в системе сломан (алиас Microsoft Store), `py` и venv от `uv` работают. Все команды идут через `uv`, pip не используется.
- **`backend/pyproject.toml` сломан.** `uv init` добавил `build-backend = "uv_build"` и скрипт `backend = "backend:main"`, но модуля `backend` нет — `uv sync` попытается собрать пакет и упадёт.
- **`docs/sql_scripts.sql` — PostgreSQL-скрипт.** `UUID`, `CREATE TYPE ... AS ENUM`, `JSONB`, `TIMESTAMPTZ`, `gen_random_uuid()` в SQLite не существуют.
- **Схема в `docs` описывает классную комнату** (`teacher_id`, `assigned_by`, роли), а продукт — самообучение. По решению пользователя схема упрощается до solo-варианта.
- **Alembic не используется** (осознанное решение ради простоты). `docs/` и модели — разные представления, при расхождении источником истины считаются модели.

## Goals / Non-Goals

**Goals:**

- Работающий срез «регистрация → вход → загрузка файла → только своё» без обращений к внешним сервисам.
- Модели и типы, переносимые на PostgreSQL без переписывания.
- Среда разработки, где весь цикл — три команды `uv`.

**Non-Goals:**

- Извлечение текста из документов, GigaChat, вопросы, попытки, статистика.
- Миграции, роли, refresh-токены, восстановление пароля, удаление материалов.
- Автоматические тесты (сценарии из `specs/` — ручной чек-лист для `/docs`).
- Frontend (отдельный change).

## Decisions

### SQLAlchemy 2.0 в синхронном режиме

`Session` + `Depends(get_db)`, без `async`/`aiosqlite`.

**Почему:** сервисы остаются линейными функциями, отладка в стектрейсах читаемая, а единственный источник конкурентности в этом срезе — локальная файловая система. Асинхронность дала бы выигрыш только на потоковых вызовах GigaChat, а их пока нет.

**Альтернативы:** async SQLAlchemy + `aiosqlite` — задел на будущее, но `await` протаскивается через каждый сервис, а профита на SQLite почти нет.

### `create_all` в lifespan вместо Alembic

Схема создаётся при старте приложения в `lifespan`-обработчике.

**Почему:** на этапе без данных миграции — чистые накладные расходы. Откат «удалить `studymate.db`» дешевле, чем написание первой ревизии.

**Цена:** `create_all` только создаёт отсутствующее. Добавить колонку в существующую таблицу он не сможет. Пока данные одноразовые, это приемлемо; при появлении значимых данных Alembic вводится одной baseline-ревизией поверх готовой схемы.

**Альтернативы:** Alembic сразу — правильнее для долгой жизни, но противоречит решению пользователя «максимально просто».

### Переносимые типы колонок

| В `docs/sql_scripts.sql` | В модели |
|---|---|
| `UUID DEFAULT gen_random_uuid()` | `String(36)`, значение из `uuid4()` в Python |
| `CREATE TYPE ... AS ENUM` | `sa.Enum(..., native_enum=False)` → `VARCHAR` + `CHECK` |
| `JSONB` | `sa.JSON` |
| `TIMESTAMPTZ DEFAULT now()` | `DateTime(timezone=True)` + `default=func.now()` |
| `NUMERIC(6,2)` | `Numeric(6, 2)` |

**Почему:** модели — единственный источник истины, а запуск на PostgreSQL остаётся возможным без переписывания. `String(36)` выбран вместо `sa.Uuid`, чтобы тип был одинаково предсказуем в SQLite и в дампе.

### `PRAGMA foreign_keys=ON` на каждом соединении

Event-listener на `connect` выставляет прагму.

**Почему:** в SQLite внешние ключи выключены по умолчанию, и `ON DELETE CASCADE` молча не срабатывает. Прагма действует на соединение, поэтому её недостаточно выставить один раз при старте.

### Абсолютный путь к файлу БД и хранилищу

Пути строятся от `Path(__file__).resolve().parents[1]`, а не от текущего каталога; переопределяются через `DATABASE_URL` и `STORAGE_DIR`.

**Почему:** `uv run` можно запустить как из `backend/`, так и из корня проекта. Относительный `sqlite:///./studymate.db` в этом случае создал бы две разные базы, и «пропавшие» данные стоили бы часа отладки.

### bcrypt напрямую

Хеширование через пакет `bcrypt`, без `passlib`.

**Почему:** `passlib` падает на `bcrypt>=4.1` при чтении версии пакета. Прямой вызов `bcrypt.hashpw`/`checkpw` — три строки и никаких транзитивных сюрпризов.

### JWT через PyJWT, логин как OAuth2-форма

`POST /auth/login` принимает `application/x-www-form-urlencoded` (`username`, `password`), отвечает `{access_token, token_type}`. Алгоритм HS256, срок жизни 24 часа, `SECRET_KEY` из окружения.

**Почему форма, а не JSON:** `OAuth2PasswordRequestForm` включает в `/docs` кнопку **Authorize**, и все защищённые эндпоинты проверяются мышкой, без копирования токена в curl. На клиенте это `new URLSearchParams(...)` — две строки.

**Почему без refresh:** срок 24 часа для разработки достаточен; refresh добавляет таблицу или инвалидацию, а в scope не входит.

**Альтернатива:** JSON-логин — приятнее для фронтенда, но теряет кнопку Authorize в `/docs`.

### Только `bcrypt`, без проверки энтропии пароля

Минимальное требование — 8 символов, без словарей и сложности.

**Почему:** учебный проект; сложность политики пароля не влияет на архитектуру и добавляется позже одной валидацией в схеме.

### Владение через единый dependency

`get_current_user` вызывается в каждом защищённом роутере, и идентификатор пользователя попадает в `WHERE user_id = :me` на уровне сервиса, а не в проверку после выборки.

**Почему:** проверка «после» легко забывается в новом эндпоинте, фильтр в запросе — нет. Чужой материал и несуществующий дают одинаковый `404`, так что существование чужих записей не утекает.

### Хранение файлов: каталог на материал

`STORAGE_DIR/materials/{material_id}/{sanitized_name}`. Материал сначала получает `id`, затем файл пишется в его каталог. Оригинальное имя хранится только в БД и отдаётся в карточке.

**Почему:** `material_id` в пути снимает коллизии одинаковых имён без переименования файла, а имя из запроса перестаёт влиять на путь. Дополнительно после построения пути проверяется, что он лежит внутри каталога материала — это отсекает `..` и разделители, если санитайзер когда-нибудь ослабят.

**Альтернатива:** хранить файлы под `uuid4()` — то же самое, но `material_id` полезнее при отладке.

### Ограничение размера при копировании, а не после чтения

Размер контролируется в процессе потоковой записи на диск; при превышении запись прерывается, файл и запись удаляются, клиент получает `413`.

**Почему:** `UploadFile` уже спуливает тело на диск, поэтому проверка «до» невозможна без ручного чтения потока; проверка «во время копирования» не даёт материалу занять место без ограничений и не требует читать файл целиком в память.

**Ограничение:** гигантский запрос всё равно успевает лечь в spool-файл Starlette до начала обработки. Для локальной разработки это приемлемо; на публичном хостинге лимит выносится на reverse proxy.

### Проверка расширения, а не MIME-типа

Белый список `.pdf`, `.docx`, `.pptx` по расширению, без сверки содержимого.

**Почему:** MIME-сниффинг из браузера недостоверен, а настоящая проверка формата появится вместе с извлечением текста, где будет обнаружение ошибок парсера.

### Ошибки: 409 на занятый username, 401 без деталей, 404 на чужое

Дубликат ловится явной проверкой с перехватом `IntegrityError` на конкурентной вставке. На входе используется одно и то же сообщение независимо от того, что именно неверно.

**Почему:** `409` вместо `400` даёт фронтенду различимый сигнал для подсветки поля; единый `401` не позволяет перебирать существующие логины.

### Конфигурация через `pydantic-settings`

`DATABASE_URL`, `SECRET_KEY`, `STORAGE_DIR`, `MAX_UPLOAD_MB` (20), `ACCESS_TOKEN_TTL_MINUTES` (1440), `CORS_ORIGINS`. Значение по умолчанию есть у всех, кроме `SECRET_KEY`: без него приложение не стартует.

**Почему:** явная ошибка при старте лучше, чем токены с предсказуемым ключом. `CORS_ORIGINS` — список, по умолчанию `http://localhost:3000` под будущий Next.js.

### `package = false` в `pyproject.toml`

Удаляются `[build-system]` и `[project.scripts]`, добавляется `[tool.uv] package = false`.

**Почему:** приложение с layout `app/main.py` не является библиотекой; без этого `uv sync` пытается собрать пакет и падает на несуществующем модуле `backend`.

## Risks / Trade-offs

- **`create_all` не умеет менять существующие таблицы** → пока данные одноразовые, схема меняется удалением `backend/studymate.db`; Alembic вводится baseline-ревизией до появления значимых данных.
- **`docs/sql_scripts.sql` расходится с моделями** → документ остаётся справочным; в `docs` стоит пометить, что источник истины — `backend/app/models/`. Задача включена в `tasks.md`.
- **Автотестов нет, сценарии из `specs/` проверяются руками** → сценарии написаны как готовые тест-кейсы, чтобы при добавлении `pytest` их осталось только перевести в код.
- **SQLite не транзакционен на уровне схемы при параллельной записи** → для одного пользователя на localhost несущественно.
- **`SECRET_KEY` в `.env` локально** → `.env` в `.gitignore`, в репозиторий попадает только `.env.example` с пустым значением.
- **Файлы на локальном диске не переживут переезд** → `STORAGE_DIR` — единственная точка, за которой начинается перенос в объектное хранилище.
- **bcrypt молча обрезает пароль после 72 байт** → ограничение длины пароля в схеме (верхняя граница) закрывает молчаливое усечение.
- **Отсутствие pip в venv от `uv`** → любой `pip install` уйдёт в глобальный Python; вся документация и задачи используют только `uv`.

## Migration Plan

Проекта ещё нет, миграции не нужны. Порядок развёртывания локально:

1. `cd backend`
2. `uv add fastapi "uvicorn[standard]" sqlalchemy pydantic-settings python-multipart pyjwt bcrypt`
3. скопировать `.env.example` в `.env`, вписать `SECRET_KEY`
4. `uv run uvicorn app.main:app --reload`
5. открыть `http://127.0.0.1:8000/docs`, зарегистрироваться, войти через **Authorize**, загрузить файл

Откат: удалить `backend/studymate.db` и `backend/storage/`, файлы приложения удаляются как обычный код. Внешних систем change не затрагивает.

## Open Questions

- **Удаление материалов** — нужен ли `DELETE /materials/{id}` в следующем change вместе с очисткой файла, или до прохождения тестов хватит накопления.
- **Пагинация списка материалов** — при десятках записей не нужна; порог, после которого добавляется `limit/offset`, определяется на практике.
