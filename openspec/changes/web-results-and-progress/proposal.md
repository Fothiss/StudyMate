# Proposal

## Why

Практика до сих пор живёт в браузере: тест, ответы и результат лежат в `sessionStorage`, поэтому при закрытии вкладки исчезают безвозвратно, а вернуться к разбору позже нельзя. Вдобавок «скрытые ответы» — только видимость: `correct_index` и `reference` приходят клиенту ещё до сдачи, их видно в devtools, а `POST /quiz/check` позволяет клиенту самому прислать эталон для проверки.

`persist-quizzes-and-attempts` уже сохранил тесты, попытки, ответы и оценки и научил сервер проверять и тестовые вопросы, и открытые ответы. Теперь клиент должен этим пользоваться, иначе сохранённые данные остаются без витрины.

## What Changes

- **BREAKING**: ответ `POST /materials/{id}/quiz` больше не содержит `correct_index` и `reference`. Клиент физически не может узнать правильные ответы до сдачи, «скрытие ответов» перестаёт быть косметикой.
- **BREAKING**: `POST /quiz/check` удаляется. Открытые ответы проверяются только для сохранённой попытки, эталоны берутся из БД.
- Сдача переходит на сервер: `POST /tests/{test_id}/attempts` сохраняет ответы и возвращает результат по тестовым вопросам, `POST /attempts/{attempt_id}/check` запускает проверку открытых. Мгновенный результат по тестовым вопросам и ожидание проверки открытых сохраняются как отдельные состояния.
- Результат читается с сервера через `GET /attempts/{attempt_id}`, поэтому разбор доступен после перезагрузки, в новой вкладке и позже по истории.
- `sessionStorage` остаётся только черновиком прохождения: идентификатор теста, данные ответы и текущий вопрос. Источником истины по результату становится БД.
- Новая страница `/results`: история попыток, разбор выбранной попытки и сводка по материалам. Раздел «Результаты» на дашборде перестаёт быть заглушкой и ведёт в историю.
- В навигации появляется пункт «Результаты».
- Локальное сравнение `answers[i] === correct_index` удаляется из клиента: счёт приходит с сервера.

## Capabilities

### New Capabilities

- `web-progress`: страница истории попыток, разбор выбранной попытки и сводка прогресса по материалам.

### Modified Capabilities

- `material-quiz`: ответ генерации не раскрывает правильные варианты и эталоны; требование `Quiz Answer Evaluation` удаляется вместе с `POST /quiz/check`.
- `web-quiz`: прохождение опирается на сохранённый тест, сдача и проверка открытых идут через эндпоинты попыток, результат читается с сервера, а в браузере остаётся только черновик.
- `web-dashboard`: раздел «Результаты» становится рабочим и ведёт в историю попыток вместо сообщения о недоступности.

## Impact

- Новые файлы: `frontend/src/pages/results/page.tsx`, `frontend/src/components/results/*`, `frontend/src/lib/attempts.ts`.
- Изменяемые файлы: `frontend/src/lib/api.ts`, `frontend/src/lib/practice-storage.ts`, `frontend/src/lib/practice-evaluate.ts` (удаляется или сводится к сбору черновика), `frontend/src/pages/practice/page.tsx`, `frontend/src/components/practice/{practice-run,practice-result}.tsx`, `frontend/src/pages/overview/page.tsx`, `frontend/src/app/router.tsx`, `frontend/src/app/shell/nav-links.tsx`, `backend/app/api/routes/{materials,quiz}.py`, `backend/app/schemas/{quiz,attempt}.py`, `AGENTS.md`.
- API: `POST /materials/{id}/quiz` теряет два поля; `POST /quiz/check` удаляется; используются существующие эндпоинты попыток.
- Вне scope: `DOCX`/`PPTX`, удаление материалов, `Alembic`, удаление старых попыток, единый итоговый балл, экспорт результатов.
